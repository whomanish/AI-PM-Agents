# Customize the skill

The canonical behavior lives in `skills/product-release-doc-writer/`. The bundled templates are starting points, not mandatory company procedures. You can adapt their section names, order, format, terminology, and optional material to your audience.

## Template precedence

For a task, use the first available template in this order:

1. A template supplied for the current task.
2. An organization or user template available in the active context.
3. The bundled template for the requested artifact.

The selected template controls presentation. It does not supply facts. If a heading requests a claim for which evidence is missing, omit that optional section or identify the gap; do not invent content to fill the space.

## Keep behavioral rules intact

Customization must preserve the skill's source hierarchy, conflict handling, evidence requirements, minimal clarification, example isolation, and internal/external audience boundaries. In particular, an internal status, risk, owner, or cohort result is not public merely because a template has a place for it. External claims require confirmed-public evidence.

Keep examples fictional and clearly labeled. Do not copy private product facts or source phrasing into templates. Add organization-specific facts only in the task's trusted context, not as generic defaults in the public skill.
